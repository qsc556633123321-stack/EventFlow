03

資料需求與表單規格

哪些資料需要收集？哪些應當設為可選欄位？

資料類別欄位內容驗證與設計備註
活動設定活動名稱、分類、說明、日期、地點、費用、總名額、單筆人數上限、審核開關建立活動必備；日期及地點目前允許空值
報名者基本資料姓名、台灣手機、Email、報名人數、備註目前後端要求姓名、09 開頭 10 碼手機、Email 與人數
自訂欄位欄位 ID、標籤、類型、必填、選項、可見性支援文字、長文字、數字、日期、下拉選單；以 JSON 保存
旅遊活動範例飲食限制、集合地點、住宿偏好、緊急聯絡人建議用自訂欄位；敏感資料依必要性收集
講座活動範例職業、學習背景、學習目標、想問的問題建議用自訂欄位
營隊活動範例監護人、緊急聯絡人、健康注意事項未成年人資料需額外同意及保護機制
報名狀態pending／confirmed／waitlisted／rejected／cancelled已實作審核、取消與候補；尚未自動遞補
媒體資源品牌 Logo、首頁 Banner、活動封面PNG／JPEG／WebP，單張上限 3 MB
平台管理主辦單位、使用者角色、Session、操作紀錄已有 owner／admin／staff 角色，需持續驗證各 API 權限

資料最小化原則：不同活動不應預設要求所有個資。報名者的自訂答案目前儲存在 registrations.custom_answers，欄位定義儲存在 events.custom_fields。

06

角色權限與公開模式

公開展示不是公開管理權限；資料與後台必須區隔。

角色與可操作範圍

  • 訪客：瀏覽公開活動、提交報名
  • staff：查看所屬組織活動及報名資料
  • admin：管理授權組織活動與品牌
  • owner：跨組織管理及建立帳號

以上是高階角色說明，具體權限以各 API 的授權檢查為準。

線上課堂公開展示

Windows 電腦 → localhost:3000 → cloudflared → HTTPS 網址 → 同學
  • 公開網址可讓外部裝置瀏覽與測試報名
  • 本機與 Tunnel 都需要持續執行
  • 管理員帳號應使用高強度密碼
  • 測試階段避免蒐集真實敏感個資
