02 角色與資料邊界
角色可管理範圍限制
訪客公開活動、報名、以查詢碼取得自己的憑證沒有管理 API 權限
owner 系統管理員平台、組織、帳號；可選定工作組織選定組織後讀寫及 CSV 均受限；完整備份須切回全域
admin 組織管理員自己的組織、活動、品牌、工作人員與活動授權不能跨組織、修改 admin/owner 或提升權限
staff 工作人員組織全部活動，或僅指定活動指定活動可分別授權審核、簽到、CSV；無成員／品牌／稽核管理

所有資源讀取、審核、簽到、通知、報表與匯出由伺服器共用 policy 驗證；前端隱藏按鈕只改善操作體驗。既有 staff 保留 organization 模式，新介面建議 assigned。公開活動跨組織可探索，報名個資不可跨組織管理。

03 模組、REST 與資料流
公開前台探索 → 詳情 → 報名 → 憑證
管理後台總覽／活動／成員／稽核
↓ JSON API / Cookie Session / CSRF ↓
Express + 共用權限政策security → validation → auth → policy → transaction + audit
↓ 參數化 SQL / 組織與活動授權 ↓
SQLite schema 28遷移前一致性備份、外鍵與完整性驗證
圖片與 Email本機圖片備援、通知佇列與重試

後端模組

  • database：歷史增量與 migration 28
  • policy：組織、活動、功能授權
  • security / validation：Session、CSRF、速率、輸入與錯誤
  • audit：操作者、結果與目標紀錄
  • members / events / registrations：成員、封存、審核交易
  • mail：通知生成、預覽、發送與重試

API 協定

  • 受保護寫入：必須傳 X-CSRF-Token
  • 從 GET /api/me 取得 Session 綁定 token
  • 錯誤格式：error、code、requestId
  • 登入：每 IP 30 次／分鐘；每帳號 10 次／10 分鐘
  • DELETE 活動：可還原封存，保留歷史
  • 管理報名 API 不回傳私有查詢碼
04 SQLite 與安全遷移
organizations → users / events　｜　events → registrations → tickets / checkins / notifications　｜　users ↔ user_event_access ↔ events
