前後台 UX已實作／部分待人工明確邀請 payload、身份清理、工作人員待授權、探索上下文、摘要與保存提醒。
Migration 與完整快照已實作schema 30、回填、一次備份、會員筆數／關聯檢查；還原新目錄並撤銷 Session／連結。

03 授權與資料結構
users → organization_memberships ← organizations → events → registrations → tickets / checkins / notifications
保留的帳號相容
  • users 舊 role／home organization／staff_mode 保留
  • 只有 users.role=owner 是平台 owner
  • 全平台 disabled 立即阻擋所有組織
有效會員資格新增
  • user＋organization 複合唯一鍵
  • admin／staff；active／suspended
  • 逐組織 staff_mode；舊 event grants 保留
  • Session 組織每次請求重新驗證
可恢復報名新增
  • key_hash／request_hash
  • event／registration 關聯 Trigger
  • 24 小時內恢復，不重複名額交易
  • 過期不直接重新建立

加入組織不搬移帳號；編輯既有資格不影響其他組織授權。組織暫停與平台停用明確分開。所有資格暫停的帳號目前需先恢復資格才能登入接受其他邀請。

04 多代理協作與交付規則

五個子代理

  • 前端：UI／流程與身份切換清理
  • 後端：會員、邀請與報名交易
  • 資料庫：migration／索引／快照
  • 資安：auth／policy 與獨立檢查
  • QA：歷史回歸、新整合測試及審查

主代理整合

  • V3_CONTRACT.json 明訂介面與檔案責任
  • 先平行實作，再資安／QA 驗證
  • 共用檔由單一責任者寫入，跨檔修正先協調
  • 正式資料先快照，測試用隔離 SQLite
  • 完整檢查與測試通過後才 Commit
