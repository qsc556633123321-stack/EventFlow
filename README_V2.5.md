# EventFlow V2.5

在 D:\Coding\EventFlow 執行 npm start，開啟 http://localhost:3000；若已有舊伺服器，請先停止再重新啟動。

- 已確認的報名可在成功畫面或首頁「報名狀態查詢」下載 QR 憑證，查詢需報名編號與原查詢碼。
- 待審核／候補需先確認，拒絕／取消無法取得或核銷。活動取消、草稿及封存禁止簽到；停止報名仍可簽到。
- 後台「報名管理」可為已確認報名顯示 QR 憑證，支援沒有查詢碼的舊版匯入資料。
- 「現場簽到」選活動後可使用相機、QR 圖片或手動輸入 EF25: 憑證內容。相機需 localhost 或 HTTPS 及瀏覽器授權。
- 每筆報名整組核銷一次，包含該筆全部人數，不支援分人次或撤銷簽到。SQLite 唯一約束與交易阻擋同時重複核銷。
- 紀錄包含時間、方式、操作人員、人數，依組織隔離；owner 跨組織，admin/staff 僅操作所屬組織。
- 總覽統計整合回獨立分頁；前後台、健康檢查及藍圖統一為 V2.5。保留原有活動、品牌、審核、自訂欄位、候補、通知、匯入與備份功能。

## 資料與備份
啟動時僅新增 tickets/checkins 表，不重建原有表或刪除資料。憑證不含姓名、Email 或查詢碼，仍應妥善保管。
JSON 備份保留 version:14 的既有結構，新增 appVersion、tickets、checkins；原 V1.3 匯入器仍只支援 V1.3，不能用來完整復原 V2.5。
完整復原需停止伺服器後備份／還原 data 及 public/uploads。upgrade-backups 保存升級前原始碼快照，不是完整資料備份。
EVENTFLOW_DATA_DIR 可指定隔離資料目錄供測試；正式使用不需設定。

## 驗證
npm run check；npm test。自動測試使用暫存資料庫、實際解碼 PNG QR、並行重複核銷、權限與狀態限制、重啟持久化，並以正式資料庫的隔離副本檢查升級資料筆數相容。
相機實機權限與 SMTP 實際投遞仍需在使用者環境驗證。V2.4 原有 nodemailer 6.x 有 npm audit 已知風險，本次未跨主要版本更換郵件套件。
